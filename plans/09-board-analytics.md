# 09 · 任务看板统计口径与多视图规划

> 结论：看板下一阶段不该继续往总览页堆数字，而应扩成 **「总览 / 效果 / 拆解 / 历史」四个视图**。
> 总览继续回答「现在要我做什么」；效果回答「这段时间干得怎么样」；拆解回答「问题集中在哪个工作区、批次、主会话」；历史回答「某条任务到底发生了什么」。
>
> 这是现有 Board 能力的扩展，不是新的 dsh 能力接缝（capability seam）：Provider 仍是 `src/board.js` + `Dispatch` 账本，Consumer 仍是 `client/index.js`，中间只扩展同源 HTTP 只读契约。不新建 `ctx` 服务，不改任务状态机，不碰 Session 格式。

---

## 一、设计目标与非目标

### 目标

1. **从状态列表升级为判断工具**：每个数字都服务于「要不要处理、哪里有问题、是否变快、是否更稳」。
2. **口径可复核**：任何比例都能看到分子、分母、时间窗、样本量和排除项。
3. **快照与统计分家**：200 条任务快照服务于当前列表；统计由 Host 对完整账本聚合，禁止把截断后的列表当全量。
4. **逐层下钻**：总览异常 → 对应工作区/批次 → 历史记录 → 任务详情/子会话。
5. **数据不足时明确说不知道**：没有数据、样本太少、字段缺失、账本被截断，分别显示，不拿 0 冒充。

### 非目标

- 不做通用 BI、自由拖拽仪表盘、工单甘特图大全。
- 不做代码行数、报告条数、token 数等「看似忙碌」的产出排名。
- 不做综合健康分、AI 效率评分等无法复核的指数。
- 没有模型用量数据时，不做成本、token 吞吐、费用估算。
- 08 的线程模型落地前，不引入「线程」指标；先保持任务为唯一分析单位。

## 二、信息架构

```text
[总览] [效果] [拆解] [历史]       窗口：24h / 7天 / 30天 / 全部
                                  工作区：全部 / 某工作区
                                  样本：n=42 · 排除归档 8 · 退休 3 · 时间未知 1

总览（默认，保持现有三段）
├─ 需要你处理
├─ 在跑与排队（含后台收尾、待读、当前并发）
└─ 最近完成

效果
├─ 结果：完成量 / 完成率 / 一次完成率 / 返工率 / 吞吐 / 并行节省
├─ 速度：队列等待 / 占用时长 / 端到端时长（P50、P90）
├─ 稳定：失败 / 阻塞 / 中断 / 取消 / 重试后恢复
└─ 趋势：按天的新派、完成、失败、耗时中位数、并行节省

拆解
├─ 工作区：目标工作区 ↔ 实际会话归属，可切换
├─ 批次：批次进度、墙钟、完成率、并行节省、最后活动
├─ 主会话：谁派了多少、在跑多少、失败集中在哪里
└─ 状态与退休原因：横向条形分布，可点选过滤

历史
├─ 全部 / 已归档 / 已退休
├─ 搜索、状态、工作区、时间、排序、分页
└─ 任务详情抽屉：生命周期、简报、报告、重试、投递、后台、错误
```

**为什么不把「效果」塞回总览**：总览是操作首页，必须在两秒内读懂；效果与拆解允许停下来分析。两类任务不应抢同一块首屏。

## 三、全局筛选与口径

### 1. 时间窗只约束统计，不隐藏当前工作

- 当前 `running` / `queued` / 后台收尾 / 待处理，无论何时创建都显示；时间窗不能让一个跑了 10 天的任务从总览消失。
- 效果、拆解、历史默认只统计窗口内事实。
- 可选 `24h / 7d / 30d / 全部`；默认沿用 `memory.window`，而不是前端另造一套默认。

### 2. 每个事实有自己的时间字段

| 统计对象 | 归属时间 |
|---|---|
| 新派任务量 | `createdAt` |
| 队列等待分布 | `startedAt`（没有开始时间的排队任务不算样本） |
| 完成量、完成率、结果分布、按天完成趋势 | 结算时刻 `settledAt` |
| 占用时长、端到端时长 | 结算时刻在窗口内的任务 |
| 归档量 | `archivedAt` |
| 退休量与退休原因 | `retiredAt` |
| 当前并发、当前后台、当前待读 | 不看窗口，取当前值 |

**需要补一个权威 `settledAt`**：现在多处把 `updatedAt` 当结算时刻，但它还可能被报告、追问等后续动作刷新。新字段只在状态进入终态时写一次；旧数据可回退 `updatedAt`，但必须标 `timeBasis: 'updatedAt-fallback'`。不能一边用会变的字段，一边宣称是精确生命周期统计。

### 3. 工作区有两个维度，不混用

- **派发目标** `workspace_id`：用户把任务派向哪里；
- **实际归属** `host_workspace_id`：子会话实际挂在哪个工作区。

总览筛选继续沿用「派发目标」；拆解页提供切换，表头必须写明当前口径。

### 4. 样本量与覆盖率是指标的一部分

每个视图固定显示：

```text
窗口内结算 n=42 · 有效耗时 n=39 · 排除归档 8 · 退休 3 · 时间未知 1
```

- `n=0` 显示 `—`；
- `1≤n<5` 可以显示数值，但必须标「样本少」；
- 缺时间、缺工作区、缺读回执的任务进入 `unknown`，不能悄悄从分母消失；
- 达到账本 cap 或统计截断时，显示「结果可能低估」，不允许装作全量。

## 四、指标字典

### A. 结果与产出

| 指标 | 定义 | 说明 |
|---|---|---|
| 完成量 | 窗口内 `status=done` 的任务数 | 不按天强行拆「今天」，按结算时间归属 |
| 完成率 | `done / (done + ended + failed + blocked + interrupted)` | **取消不进入分母**；取消率单列，避免用户主动取消拉低或抬高成功率 |
| 一次完成率 | `attempt=1 且 done / attempt=1 的已结算任务` | 同样排除取消；衡量不返工完成的比例 |
| 返工率 | `attempt>1 / 全部派发任务` | 任务级，不把每次 attempt 当成新任务重复计数 |
| 取消率 | `cancelled / 全部已结算（含 cancelled）` | 与完成率分开，不混成「成功率」 |
| 失败率 / 阻塞率 / 中断率 | 对应状态 / 已结算 | 三项分开，不能用「失败」一个词覆盖 |
| 重试后恢复率 | `attempt>1 且 done / attempt>1 的任务` | 当前 attempt 可支持的近似值；若以后要精确按每次失败计算，需保存尝试历史 |
| 吞吐 | `done / 窗口自然日数`；同时给总量 | 不用「有任务的天数」做分母，避免低活跃期数字虚高 |

### B. 速度与等待

| 指标 | 定义 | 注意 |
|---|---|---|
| 队列等待 | `startedAt - createdAt` | 没启动过的 queued 不进入分布，另列当前排队时长 |
| 占用时长 | `settledAt - startedAt` | **包含后台收尾**，不能叫「纯模型执行时长」 |
| 端到端时长 | `settledAt - createdAt` | 约等于队列等待 + 占用时长 |
| P50 / P90 | 对上述三个时长分布取分位数 | P50 看典型，P90 看长尾；不要只给平均数 |
| 长尾比 | `P90 / P50` | P50=0 时显示 `—`；只作异常提示，不当目标 KPI |
| 当前排队最久 | `now - 最早 queued.createdAt` | 是当前运营信号，不是历史分布 |

「后台收尾时长」需要单独记录 `backgroundClearedAt` 才能准确拆出；没有该字段前不估算「真正执行时长」。

### C. 并行效果

保留现有粗略口径，并明确它不是工时结算：

```text
任务占用总和 = Σ(settledAt - startedAt)
墙钟跨度     = max(settledAt) - min(startedAt)
并行节省     = max(0, 任务占用总和 - 墙钟跨度)
并行倍数     = 墙钟跨度 > 0 ? 任务占用总和 / 墙钟跨度 : —
```

- 只统计窗口内、时间完整的已结算任务；
- 快照不足、窗口跨度过大、样本少时都标注「估算」；
- **时间加权并发利用率**（这段时间平均用了多少槽位）不能用两个时刻的快照代替，见 §六。

### D. 稳定性与投递健康

| 指标 | 当前能算什么 | 限制 |
|---|---|---|
| 报告未送达 | `delivery.outcome=failed` 的当前记录数 | `delivery` 只留最后一次，不能当历史失败率 |
| 当前待读 | `inputPendingAt && !inputReadAt` | 已有 |
| 待读年龄 | `now - inputPendingAt` | 当前最后一次追问；TTL 后进入 unknown |
| 读回执时延 | `inputReadAt - inputPendingAt` | 只有最近一次追问，历史覆盖率需另记消息流水 |
| 后台收尾数 / 最老后台年龄 | `background.jobs/subagents/since` | 当前快照可直接算 |
| 归档失败 | `archiveError` 非空数 | 直接列出原因，不归一化成模型错误 |

### E. 记忆与历史健康

复用 `memoryStats()`，不另造口径：

- 活表任务数、归档数、退休数、退休留痕被丢弃数；
- 准入 direct / ledger 比例；
- pending / unknown 输入数；
- 当前窗口、单条报告预算。

看板展示「活表 + 退休 = 曾经有过」的守恒关系，避免退休被误读为删除。

## 五、四个视图的详细设计

### 1. 总览：保留操作首页，只补三个信号

不推翻 06 的三段结构，只增加：

- **健康角标**：未送达、待读超时、后台收尾超时；
- **当前排队最久**：比「排队 n」更能说明是否饿死；
- **样本口径入口**：点击效果带进入「效果」视图，不继续往首屏加卡片。

### 2. 效果：回答「这段时间怎么样」

布局顺序：

1. **结果卡**：完成量、完成率、一次完成率、返工率、吞吐、并行节省；
2. **速度卡**：队列等待 P50/P90、占用时长 P50/P90、端到端 P50/P90；
3. **稳定卡**：失败、阻塞、中断、取消、重试后恢复；
4. **趋势区**：按天展示新派、完成、失败/阻塞/中断、耗时中位数、并行节省；
5. **并行区**：占用总和、墙钟跨度、并行节省、并行倍数；时间加权利用率待数据就绪后加入。

趋势图规矩：

- 柱/线都由 Host 按天聚合，前端不拿 200 条列表伪造全历史；
- 完成量用绿色、失败/阻塞/中断用红/橙并带文字，不以颜色单独表意；
- 每个点可查看当天明细，不要求悬浮才能读数；
- 提供「图表 / 表格」切换，保证可访问与可复制。

### 3. 拆解：回答「问题集中在哪」

**工作区表**：

| 工作区 | 在跑 | 排队 | 完成 | 完成率 | P50 占用 | 失败 | 阻塞 | 并行节省 | 最后活动 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|

**批次表**：

| 批次 | 进度 done/total | 在跑 | 待处理 | 批次墙钟 | 并行节省 | 最近报告 |
|---|---|---:|---:|---:|---:|---|

批次墙钟 = `max(updatedAt) - min(createdAt)`；全部成员已结算才停止增长。

**主会话表**：按 `parent_session_id` 聚合，显示派发数、在跑、完成率、失败数、最后活动。适用于「任何会话都能派发」的现状，避免默认主会话掩盖其它来源。

**状态与退休原因**：用横向条形列表，不用九色 donut。退休原因直接使用稳定代码（如 `cap-count` / `cap-days`），错误文本不拿去猜类别。

点击任一行：把对应工作区/批次/主会话设为过滤条件并回到总览；顶部给「已筛选 ×，清除」。

### 4. 历史：回答「这条任务发生了什么」

- 子视图：`全部 / 已归档 / 已退休`；
- 搜索：`task_id`、标题、worker_session_id、工作区；
- 筛选：状态、工作区、时间、是否重试、是否有后台；
- 排序：创建/结算/耗时/状态；
- 表格替代无限长卡片列表，超过 50 条分页或分段加载；
- 退休行不假装能打开子会话，只复制 id 与查看留痕。

**任务详情抽屉**是本视图的核心增量，包含：

- 生命周期：创建 → 开始 → 报告 → 结算 → 归档/退休；
- 简报与目录、目标工作区、实际归属；
- 报告列表与最后一次输出；
- attempt、错误、归档失败；
- 追问投递/读取、后台 job/subagent、prepare 结果；
- 有活会话时打开，无活会话时复制 id。

## 六、数据契约与边界

### 1. 保留 `/board` 快照，新增只读聚合

建议新增 `GET /board/stats`（与 `/board` 同一套同源准入），而不是把完整聚合塞进每 2 秒轮询的任务快照。

```text
{
  statsVersion,
  generatedAt,
  scope: { window, workspaceId, hostWorkspaceId },
  coverage: { sourceTasks, inWindow, settled, validDurations,
              excludedArchived, excludedRetired, missingTimes, truncated },
  summary: { outcome, durations, parallel, reliability },
  daily:   [{ day, created, done, failed, blocked, interrupted, medianDuration, saved }],
  groups:  { workspaces, batches, parentSessions, statuses, retiredReasons }
}
```

- Host 对活表与退休留痕分别聚合；统计默认排除归档/退休，历史审计单独读取；
- `statsVersion` 允许以后加字段而不破坏旧客户端；
- `/board` 的 200 条上限不变；`/board/stats` 不带任务正文，响应保持轻量；
- 统计失败时返回 `null`/降级说明，不影响现有任务列表。

### 2. 现在就能算 vs 需要补数据

| 立即可做（完整账本聚合即可） | 需要补字段/事件 | 当前不应承诺 |
|---|---|---|
| 结果、速率、时长分位数、并行粗算 | 权威 `settledAt` | 精确模型执行时长 |
| 工作区/批次/主会话分布 | 后台开始与清空时刻 | 时间加权并发利用率 |
| 按天结果与耗时趋势 | 每条消息的投递/读取流水 | 历史投递成功率、平均确认时延 |
| 当前待读、后台年龄、归档失败 | 稳定错误码 | 按错误类型可靠聚合 |
| 当前记忆治理指标 | 尝试历史（若要按 attempt 细分） | 成本、token、费用 |

### 3. 时间加权并发的唯一正确来源

若以后要做「平均并发 / 槽位利用率 / 并发曲线」，需要 Host 记录**有界样本或状态变化事件**（例如每 5 秒采样或 running 数变化时记录），再按时间积分。不能用「当前 3/6」反推过去一天的利用率，也不能从任务起止时间精确还原所有槽位变化（追问软上限、后台收尾都会使任务数与会话数不同）。

## 七、分期

### P0 · 先统一口径

- 增加 `settledAt` 与旧数据 fallback 标记；
- 落地 `boardStats` 聚合与 coverage；
- 给现有四个效果数字补分子、分母、样本量；
- 固定时间、边界、缺失字段的单元测试先行。

**验收**：同一批任务，总览、效果、拆解三个视图的完成数与完成率完全一致。

### P1 · 上线「效果 + 拆解」

- 结果/速度/稳定卡；
- 按天聚合；
- 工作区、批次、主会话三张表；
- 点击下钻与清除筛选；
- 图表/表格双形态。

**验收**：夹具含 1000 条任务、归档与退休混合时，统计不受 200 条快照上限影响；所有比例可追到分子分母。

### P2 · 上线「历史 + 详情抽屉」

- 搜索、筛选、分页、退休留痕；
- 生命周期与报告详情；
- 可导出当前筛选的 CSV（可选）。

**验收**：任何已归档/退休任务都能回答「何时、为什么结束」；不存在的会话不会假装能打开。

### P3 · 有证据后再加实时与成本

- 有界并发采样 → 时间加权利用率；
- 消息级投递流水 → 历史投递成功率与确认时延；
- 稳定错误码 → 失败类型分布；
- 宿主提供真实模型用量后再做 token/成本；
- 08 落地后再加线程视图，不在任务视图里提前混入口径。

## 八、验收清单

1. **同源**：同一筛选条件下，总览、效果、拆解的完成数、完成率一致。
2. **全量**：1000 条任务 + 200 条快照上限时，统计明确按完整账本计算并显示 coverage。
3. **边界**：窗口起点恰好相等、跨天、时钟回拨、缺 `startedAt` / `settledAt` 的任务都有确定结果。
4. **不混淆**：完成率不含取消；占用时长不叫执行时长；目标工作区与实际归属不混用。
5. **不投票**：归档/退休不进入效果指标，但历史与审计可查。
6. **不装全量**：样本不足、时间未知、字段缺失、账本截断分别可见，不能统一显示 0。
7. **下钻一致**：工作区/批次/主会话表点击后，回到总览的任务集合与计数一致。
8. **可读**：图表有表格等价物；颜色之外有文字；键盘可达；小屏可折行。
9. **可追溯**：每条历史记录都能解释「创建、开始、结算、归档/退休」；详情与账本一致。
10. **可回退**：stats 接口不可用或字段缺失时，总览仍按现有快照工作，不白屏、不报错循环。

---

## 九、明确不做

- 不做面向 agent 的工单管理、拖拽看板、审批流。
- 不做「生产力评分」「健康总分」「今天比昨天聪明多少」。
- 不用报告条数、消息长度、工具调用次数衡量工作量。
- 不用一个 2 秒轮询快照伪造历史曲线或并发积分。
