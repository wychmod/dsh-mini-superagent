# 06 · 任务看板重新规划：从流水账到指挥台

> 现状：0.5.0–0.8.x 的面板是一张按状态排序的平铺列表。它能回答「有哪些任务」，
> 但回答不了「派发到底带来了什么」「现在哪条需要我」「这条为什么停住」。
> 本文件记录这次重排的判断依据与取舍；实现见 `client/index.js`。

## 一、问题拆解

| 症状 | 根因 |
|---|---|
| 像流水账 | 所有任务同构：一行标题 + 一行摘要。完成的和失败的、跑着的和排队的，视觉权重一样 |
| 看不出「派发效果」 | 只有并发/排队/总计/失败四个计数，都是「当前状态」，没有「完成了多少、省了多少时间」 |
| 找不出该管哪条 | 失败与阻塞混在列表里，靠状态点颜色区分；原因要打开子会话才知道 |
| 批次看不出进度 | 只有 `批次` 徽标，没有「3/5 到哪一步」 |
| 长任务看不出异常 | 只有走表的耗时数字，没有「这条比同类慢多少」的参照 |

## 二、参考了什么

1. **上游 `dsh-superagent-prototype` 的 Web 面板**（本地 `reference/`，同宿主、同槽位、同设计语言）。
   借的是它的信息结构，不是样式：`Section(title, count, action)` 分节、`dt-stats` 顶部统计、
   「需要人处理的先列」的排序（它的 `OverviewPage` 就是 `pendingTickets` → `problems` → `lastDay` → executor）、
   以及「每个数字都能点进去看明细」的可下钻习惯。
2. **通用仪表盘惯例**：先给结论（effect numbers），再给异常（attention），最后给明细（list）。
   Linear / Vercel 一类工具的共识是「默认视图只显示需要注意的东西」，历史默认折叠。
3. 社区里的 DSH 看板插件（`dsh-taskboard` 等，300+ star）确实是 board/list/Gantt 多视图 + SQLite 工单模型，
   但那套是「给 agent 用的项目管理」，和本插件的「派发观测」不是一回事。**没有照搬**：
   我们不需要拖拽看板、工单关系、Gantt，需要的是「这次派发值不值」。

## 三、新的信息架构

```text
┌ 头部：并发 3/6 · 排队 1 · 总计 9 · 失败 1            更新于 12:31:04 ┐
│ 效果：完成 4   成功率 80%   平均耗时 1 分 08 秒   并行节省 6 分 21 秒 │
│ 并发条 ▓▓▓▓▓░░░  排队 1   后台收尾 1                                │
│ [全部 9] [进行中 4] [需要处理 2] [已归档 3]          工作区 ▾  立即归档 │
├──────────────────────────────────────────────────────────────────────┤
│ 需要你处理 2                                                          │
│  ● 失败   给结算接口补一个集成测试      原因 模型侧 503…      1 分 13 秒 [重试] │
│  ● 阻塞   把 CI 缓存换到 pnpm store     原因 需要组织级 token…  51 秒   [重试] │

│ 在跑与排队 4                                                          │

```

**为什么是这三段**：面板要回答三个问题，顺序就是优先级——
「有什么要我做」（attention）→「现在在干什么」（active）→「干成了什么」（done）。
历史（归档）进单独视图，默认不占空间。

## 四、效果数字怎么算（都不编）

| 数字 | 定义 | 为什么这么定 |
|---|---|---|
| 完成 | 快照里 `status=done` 的已结算任务数 | 最直白，不做时间窗（跨天任务也算），避免「今天」在深夜看起来像 0 |
| 成功率 | `done ÷ 已结算`（含 cancelled / interrupted） | 分母必须含失败与中断，否则「取消了 8 个」会让成功率虚高 |
| 平均耗时 | 已结算任务耗时的**中位数** | 用平均会被一个 40 分钟的任务拉飞；中位数才是「典型一条要多久」 |
| 并行节省 | `Σ 各任务耗时 − 墙钟跨度`，都为 0 时显示 `—` | 串行做这些活要花前者，实际只花了后者。快照只含最近 200 条、跨天会失真，所以 hover 里明写「粗算」 |

`elapsed_ms` 由服务端给（已结算的停在结算时刻，未结算的走到现在），前端只用不改。

## 五、实现取舍

- **只动呈现层**：轮询、写操作、打开子会话、归档、错误提示全部沿用。
  新增的 `effectStats` / `median` / `sortAttention` / `groupActive` / `batchProgress` 都是纯函数，离线可测。
- **保留 DOM 契约**：行仍是 `.dsh-sa-row` + `data-status` / `data-archived`，冒烟脚本按它找行、点行。
  换布局顺手改契约，下次改样式就会误伤测试。
- **一个组件三种密度**：`TaskCard` 的 `dense` 用于完成/归档，避免维护两套行。
- **不引入图表库**：并发条、批次进度、耗时进度都是 div + 宽度百分比。零依赖是无构建约束的直接结果。
- **小屏**：所有新块都是 flex-wrap，数字与标签会折行；没有固定宽度。

## 六、验证到哪一步

- 离线渲染冒烟 **87 项**（新增 6 条：三段结构、四个效果数字、原因行、批次 `0/2` 进度、后台收尾、待读）。
- 单测 **158 条**不受影响（`client/` 不进 node --test）。
- **未做**：真浏览器里的版式（间距、折行、深色主题对比度）。本机浏览器截图工具报错，没验成；
  `preview/board-preview.html` 是给这一步用的——打开就能看，白色主题，真实组件 + 假数据。

## 七、下一步可做

1. 真机目视一遍，按截图微调间距与断点；
2. 「并行节省」加一个 7 天小柱图（需要服务端给按天聚合，现在快照只有 200 条，前端算会失真）；
3. 点开某条任务时给一个侧栏详情（简报、最近 5 条报告、后台活），替代现在的「跳子会话」单一动作。
